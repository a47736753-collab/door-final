# DoorsOpen implementation outcomes

- [x] **Readiness overview and priority queue** — Display a readiness score, unresolved conflicts, incomplete tasks, event countdown, and priority actions. Rank issues by severity, event proximity, and operational impact and explain why each needs attention. Make dashboard metrics clickable so they navigate to the relevant issues. Use real deterministic checks and clearly identified sample event data; do not show fake success messages or invented statistics.
  - Evidence: `client/src/features/doorsopen/checks.ts` derives the score and priority; `components/Overview.tsx` renders the dashboard/actions; sample-data provenance and session-only behavior are visible in the interface.

- [x] **Schedule, validation, and conflict detection** — Provide calendar/timeline views with overlap detection. Validate missing fields, invalid times, duplicate records, and inconsistent assignments. Find session overlaps only when times overlap and the sessions use the same room; compare expected attendance with venue capacity; find simultaneous volunteer assignments and availability mismatches; detect simultaneous bookings of the same equipment; identify incomplete or overdue preparation tasks. Highlight conflicting sessions, overloaded rooms, double-booked equipment, and volunteers assigned to simultaneous activities, with clear severity indicators and explanations.
  - Evidence: `components/Schedule.tsx`, `checks.ts` and `import-data.ts`; exact same-room and Room C/P1 behavior covered in `server/doorsopen-rules.test.ts`.

- [x] **Interactive venue map** — Show an interactive floor plan with stages, rooms, food stalls, registration desks, first-aid stations, exits, and accessible routes. Selecting a location reveals its schedule, capacity, and resource status; connect locations to venue records, schedules, and resource status. Provide room capacity, locations, warning indicators, and linked volunteer/equipment details where relevant.
  - Evidence: `components/VenueMap.tsx` renders keyboard-selectable locations, linked issue status, bookings, capacity, named volunteers and equipment status.

- [x] **Conflict dependency graph** — Connect each issue to the sessions, people, venues, or resources it affects. Clicking a conflict highlights its connections and the affected records. Provide search and filters, zoom, pan, graph reset controls, and smooth graph interactions; make the graph and issue selection navigable and understandable.
  - Evidence: `components/ConflictGraph.tsx` implements SVG dependency nodes/edges, search, severity filtering, zoom, pan, reset and linked issue navigation.

- [x] **What-if impact simulator** — Let organisers move a session, change its time, or reassign a resource on a copy of the plan. Rerun affected room, capacity, volunteer, equipment, and dependency checks. Compare the proposed plan with the original and show which conflicts disappear, which remain, and whether new conflicts appear elsewhere. Demonstrate Robotics Workshop conflicting with a Coding Session in Room A from 10:00–11:00 AM and projector P1 double-booked for both activities. Permit moving Robotics Workshop to Room C when Room C has sufficient capacity and is available. Mark the Room A issue resolved only if the updated data passes its check; keep projector P1 unresolved/recheck-needed until reassigned or confirmed available. Never claim an issue is fixed or the plan is ready unless relevant updated checks pass. Provide clear proposal, apply, and discard interactions.
  - Evidence: `components/WhatIfSimulator.tsx` compares an isolated proposal and keeps the P1 issue visible; simulation assertions in `server/doorsopen-rules.test.ts` confirm the room issue clears while P1 remains.

- [x] **Resources, tasks, and data import/validation** — Track rooms, equipment bookings, volunteer assignments and availability, preparation checklists, and task completion. Identify incomplete or overdue tasks. Support organiser schedule/resource data uploads from CSV/Excel as defined in the brief, validate missing fields, invalid times, duplicate records, and inconsistent assignments, and give helpful explanations rather than claiming invalid data was imported.
  - Evidence: `components/ResourcesTasks.tsx`, `components/ImportDialog.tsx`, and `import-data.ts` support CSV/Excel import, an example template, atomic validation feedback, and interactive resource/task state.

- [x] **Readiness reports** — Generate a report that summarizes critical conflicts, remaining warnings, completed checks/tasks, and recommended actions from the current plan. Make report output usable for review/export.
  - Evidence: `components/Reports.tsx` computes the current summary and recommendations and offers print and CSV export.

- [x] **Command-centre presentation and user flow** — Deliver a premium dark navy interface with violet and cyan accents, clear visual hierarchy, smooth interactions, responsive design, and a polished empty state. Use live-style updates when simulations run, clear severity indicators, helpful explanations, and interactive map markers/graph paths. Preserve this workflow: open DoorsOpen; select or create an event; import schedules/resources; validate data; run readiness checks; explore the dashboard and venue map; inspect the conflict dependency graph; choose a proposed fix; simulate changes; if checks fail, review the report/actions; if all relevant checks pass, let the organiser confirm the final plan. The product should combine a command-centre dashboard, clickable venue map, interactive dependency graph, and working what-if simulator.
  - Evidence: `client/src/pages/Home.tsx` and `client/src/index.css`; event creation, search, notices, import, simulation, guarded confirmation and explicit session-only data disclosure are wired into the responsive shell.

- **Delivered verification evidence:** `pnpm check` passed; `pnpm test` passed (10 tests across 3 files); `pnpm build:static` passed and split the XLSX parser/workspaces into lazy chunks; `GET /manus-routes.json` returned HTTP 200 with the route manifest JSON.
